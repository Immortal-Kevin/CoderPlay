# Desktop Cleaner v1.0 测试摘要

测试日期 2026-11-23。实机为 Windows 11 x64 26H2，Build 26300。先由 Codex 完成只读检查及模拟测试，再由用户实测真实图标。P5 便携发布以主屏通过、副屏限制已知为验收范围。

| 检查项 | 结果 | 观察 |
| --- | --- | --- |
| 主程序、恢复程序、测试的 x64 Release 构建 | PASS | 三个项目编译通过，0 个警告和 0 个错误 |
| Shell 枚举、位置读取和可访问性边界 | PASS | 实机反复读到 39 个图标、39 个不同坐标和 39 个可见边界。两次读取的标识及位置一致 |
| 实机只读网格计算 | PASS | 主屏 3120×2080、250% 缩放，建议窗口的网格可容纳 39 个图标。副屏 1920×1080、100% 缩放，当前网格下工作区只容纳 24 个 |
| 实机主窗口启动和退出 | PASS | 主屏 250% 缩放，主窗口 1150×850 物理像素。两个操作按钮和 39 个图标的计数可见且位于窗口内，空闲时正常关闭 |
| Windows x64 自包含程序验收 | PASS | .NET 8.0.33。主程序正常启动、显示 40 个当前图标并正常退出，紧急恢复工具只读探测通过。 |
| 模拟桌面自动化测试 | PASS | 15/15。覆盖坐标读取、快照校验与禁止覆盖、备份失败禁止移动、同名身份、新增及删除图标、10 次拖动状态、同目标防重复、空桌面、容量、自动排列拒绝、并发、部分写入回滚和重建管理器后读取恢复数据 |
| 原布局恢复与关闭前恢复 | PASS（模拟恢复）；NOT TESTED（实机） | 模拟 Shell 恢复后逐项比对原始坐标，失败时保留原始快照，新管理器可以继续恢复。用户实测反馈未包含原布局坐标对比或关闭前恢复 |
| 真实图标整理、拖动露出及释放迁移 | PASS（主屏）；FAIL（副屏） | 用户在实机执行并确认主屏通过、副屏未通过。此前副屏容量估算为 24 个，副屏失败的具体原因未单独验证 |
| Explorer 重启、异常退出后的实机恢复 | NOT TESTED | 模拟测试覆盖保留恢复数据和新管理器恢复 |
| 实机 100%、125%、150% 窗口布局及自动排列、对齐网格切换 | NOT TESTED | 读取了副屏 100% DPI，只读检查阶段未改变主机设置，用户后续实测未包含 DPI 专项 |

在授权的测试账户验收时，先准备至少 20 个真实桌面图标。记录原布局，点击整理，拖动标题栏并确认拖动过程中图标留在旧位置，释放后全部迁移到窗口下方，重复 10 次。再测试键盘移动和关闭自动恢复，逐项比对恢复坐标。最后验证 Explorer 重启、主程序异常退出、125% 缩放、自动排列开启和网格对齐设置。可用 `DesktopCleaner.Recovery.exe --probe` 先验证该环境的 Shell 可读性和容量。

若 Shell 拒绝位置或对齐到其他网格，程序会报告实际回读失败并尝试恢复。副屏真实交互未通过，发布说明保留该限制。
